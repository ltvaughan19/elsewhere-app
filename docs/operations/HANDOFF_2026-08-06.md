## 2. Strategic decisions locked this period (and why)

### 2.1 Proof product — complete-enough, deliberately narrow

**Decision:** Ship a **complete-enough-for-initial-proof** product, not a three-corridor encyclopedia before any users.

| In | Out (veto) |
|----|------------|
| Philippines corridor only | Open/deepen Thailand or Mexico |
| Keep published PH Entry & Stay | Fill additional portal sections |
| Free habit surfaces complete | AI coach, document vault, partner directory, community |

**Why:** Filling shelves before warm users take one official next step recreates a brochure OS, burns solo MFA verification capacity, and delays learning whether the leaving habit works. Owner may later override; until then agents must not scope-creep.

### 2.2 Free vs paid (proof monetization)

**Free (must stay complete and un-gated):**

- Fit Quiz → research path  
- Published PH Entry & legal stay + Sunday Action + trust strip + done this week  
- Passport checklist, basic budget, compare (published data only)  
- Dashboard always surfaces the one next action  

**Hard rule:** Never paywall the Free Sunday Action.

**Explorer — $19/mo (locked; was $12 in old marketing copy):**

- Sunday Action history + streak  
- Multi-device plan sync  
- Living personal roadmap (30/60/90 open items that persist)  
- Lightweight source-change alerts on published PH claims  
- Deeper budget/runway + progress summary  

**Serious Move — $149 one-time:**

- Structured 30/60/90 pack from quiz/plan + **currently published PH claims only**  
- Regenerable later  
- **Stacks** with Free or Explorer  

**Entitlement model (locked):**

- `profiles.plan_tier` = subscription only: `free` | `explorer`  
- `profiles.serious_move_purchased_at` = one-time pack (nullable timestamptz); survives Explorer cancel  

**Builder / Concierge:** Shown as muted “Coming later” on `/pricing` — **no purchase path**.

**Why $19 / stacking:** Continuity is what justifies paid after habit; one-time pack must not wipe subscription state. Single `plan_tier` enum cannot hold both — hence the separate timestamp column.

### 2.3 Implementation sequence (paid) — follow in order

1. Stripe Checkout + Customer Portal + webhooks → `plan_tier` + `serious_move_purchased_at`  
2. Feature gates for paid entitlements  
3. Living roadmap + progress summary (extend `user_plans` JSON + dashboard UI)  
4. Serious Move pack generator  
5. Lightweight source-change alerts (MVP)  

**Status:** Step 1 **code + DB migration shipped**; human must finish Stripe test products/keys + smoke test. Step 2+ not started.

### 2.7 Exchange rates (decided — not built yet)

**Decision:** Provide **easy, accurate FX** on the site via a **scheduled pull** from a reliable API (Open Exchange Rates, ECB, or similar).

| Requirement | Detail |
|-------------|--------|
| Effort posture | Low-effort, accurate — schedule + cache; not manual CMS rates |
| Placement | Strategic (budget tools, corridor money context, compare) — not a buried footnote |
| Scope | **Corridor-agnostic platform feature** — works for PH now and for every future corridor without rewrite |
| Architecture | Content/platform rule: rates are **data + config** (base/quote pairs), not hardcoded PHP/THB/MXN UI |

**Why now as a decision:** Money realism supports “what do I do next?” without inventing visa facts. Doing it as platform FX avoids per-country rewrites.

**When to build:** After Stripe Step 1 smoke + Step 2 gates (or in parallel only if it does not delay paid proof). Label rates as **planning estimates**; cite source + as-of timestamp.

**Suggested shape (for implementer later):**

- Worker/cron fetches base USD (or configurable) → store snapshot table or edge cache  
- UI: budget calculator + corridor Money/Overview surfaces when those exist; Free can show basic convert; deeper runway tracking stays Explorer  
- Never present FX as tax/legal advice
